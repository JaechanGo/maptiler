빠른 시작 — 드롭인 교체

기존 MapTiler Cloud 코드에서 style URL 한 줄만 바꾸면 됩니다. center/zoom/pitch 등 나머지 옵션은 그대로 둡니다.

const map = new maplibregl.Map({
  container: 'map',
  style: '__ORIGIN__/styles/cuvia/style.json',   // ← 이 한 줄만 교체 (API 키 불필요)
  center: [126.9779, 37.5663],   // [경도, 위도] — Leaflet 의 [위도, 경도] 와 반대
  zoom: 15, minZoom: 5, maxZoom: 22,
  pitch: 45, bearing: -17.6
});
map.addControl(new maplibregl.NavigationControl({ visualizePitch: true }));

마커 찍기 (소비 프론트 책임)

좌표 순서는 [경도, 위도] 입니다. 소량은 DOM 마커, 대량은 GeoJSON 소스 + circle/symbol 레이어를 쓰세요.

// 소량(수십~수백): DOM 마커
new maplibregl.Marker()
  .setLngLat([127.0, 37.5])
  .setPopup(new maplibregl.Popup().setHTML('<b>이름</b>'))
  .addTo(map);

// 대량(수천~수만): GeoJSON 소스 1개 + 레이어
map.addSource('pts', { type: 'geojson', data: featureCollection });
map.addLayer({
  id: 'pts', type: 'circle', source: 'pts',
  paint: { 'circle-radius': 5, 'circle-color': '#e24b4a' }
});
// 갱신: map.getSource('pts').setData(nextCollection);

검색 연동 (지오코딩 / 역지오코딩)

전국 도로명주소 + 역·지명 + 상가/시설 통합 인덱스. 결과에 전체주소·지번·우편번호·전화·업종이 함께 옵니다. 게이트웨이 경유 시 같은 origin 으로 호출됩니다.

// 지오코딩: 이름/주소 → 좌표
const r = await fetch('/geocode?q=' + encodeURIComponent('증미역')).then(x => x.json());
// r.results[0] = { name:'증미역', kind:'station', lon:126.8618, lat:37.5575, address:{ ... } }
map.flyTo({ center: [r.results[0].lon, r.results[0].lat], zoom: 16 });

// 역지오코딩: 좌표 → 주소 + 최근접 장소 + 포함 행정경계
const rev = await fetch('/reverse?lon=126.8618&lat=37.5575').then(x => x.json());
// rev.address={ ... }, rev.nearest=[{ name, kind, dist_m, ... }], rev.areas=[{ name, type, code }]
// ↓ 전체 요청/응답 필드는 아래 "지오코딩 API — 요청 / 응답 스키마" 참고

지오코딩 API — 요청 / 응답 스키마

프론트가 결과 화면을 설계할 수 있도록 요청 파라미터와 응답 필드를 정리했습니다. 모든 응답은 application/json; charset=utf-8 · CORS 허용(*) · 좌표는 [경도(lon), 위도(lat)]. (예시의 값은 구조 설명용이며 실제 값은 데이터에 따라 다릅니다.)

응답 필드

필드타입설명
querystring요청 검색어 echo
contract_versionstring응답 분해계약 버전 신호 — 현재 "geocode/2". 신계약(display/structure/category) 분기 판단용
results[]array매칭 결과 — 관련도 점수순
results[].namestring표시명 — 주소면 풀 도로명주소(법정동·건물명), 그 외는 고유명. display.full alias
results[].kindstring종류 — addr · road · place · station · dong · poi · biz · facility
results[].displayobject2단 표기용 { main, secondary, full }(아래) — 전 kind 항상 부착
results[].lon / latnumber좌표 [경도, 위도]
results[].subtypestring·null세부 종류(이름 결과). 주소 지번경로는 "parcel", 그 외 주소 결과엔 없음
results[].addressobject·null구조화 주소(아래). 주소 결과는 자기 주소, 그 외는 최근접 주소 부착
results[].categoryobject(선택) 업종·분류 — 아래. 없으면 키 자체 미부착
results[].phonestring(선택) 전화번호 — 상가·시설
results[].sourcestring(선택) 데이터 출처

display 객체 — 화면 표기용 2단 + 전체

필드타입설명
mainstring주표시(굵게) — 결과명/도로명주소 본문
secondarystring·null보조표시(회색) — 카테고리/유형 · 지역. 없으면 null
fullstring전체 1줄 — 마커/입력창 라벨용

표기는 display 우선 — 미지원/구버전 응답이면 main=name fallback. 영문 kind 원문은 노출하지 않습니다.

address 객체 — 도로명·지번·우편번호·행정코드

필드타입설명
roadstring표준 도로명주소 (법정동 제외)
parcelstring지번주소
zipcodestring우편번호
bldstring건물명 (없으면 빈 문자열)
structure.sido / sigungu / emdstring시도 / 시군구 / 읍면동(법정동)
structure.haeng_dongstring·null행정동
structure.ristring·null리(里). address 무컬럼이라 현재 null 고정
structure.sanboolean·null산(山) 지번 여부 — 지번경로(parcel)만, address 결과는 null
structure.road_namestring·null도로명
structure.main_no / sub_nostring·null도로명 건물 본/부번 (지번 본번이 아님 — 지번은 ji_main/ji_sub)
structure.bld_main_no / bld_sub_nostring·null건물 본/부번 — main_no/sub_no 의 의미 명시 alias
structure.ji_main / ji_subinteger·null지번 본번 / 부번
structure.bld_namestring·null건물명(없으면 빈 문자열)
structure.zipcodestring·null우편번호(structure 내 사본)
structure.b_codestring·null법정동코드
structure.h_codestring·null행정동코드

category 객체

필드타입설명
groupstring·null업종 대분류 그룹 (= primary, cat1)
pathstring·null분류 경로 — "cat1>cat2"(구분자 >, 공백 없음). display.secondary 우선 키
primarystring(선택) 업종 대분류 — 상가(biz)
labelstring표시 라벨 (예: 음식 > 카페/디저트, 또는 종류명)
substring(선택) 중분류 — 상가(biz)

# areas 는 좌표를 포함하는 경계가 없으면 빈 배열 []. nearest[*] 에도 display 부착(geocode 와 동일).

응답 필드

필드타입설명
lon / latnumber요청 좌표 echo
addressobject·null좌표가 속한 도로명+지번 주소 (구조는 위 address 와 동일)
nearest[]array최근접 장소 — 거리순. 각 항목은 /geocode results 와 동일(display·address.structure 부착) + dist_m

areas[]array좌표를 포함하는 행정경계. 포함하는 경계가 없으면 빈 배열 [] (프론트 빈배열 가드 필요)
areas[].name / type / codestring경계명 / 종류(법정동·행정동 등) / 행정코드

GET/health — 적재 상태 확인

정상 응답 — 인덱스 적재 건수 확인용

{ "ok": true, "places": 11281251, "areas": 4382 }

places = 검색 인덱스 건수(약 11,281,251). areas 수치는 환경별로 상이할 수 있습니다. 필수 테이블이 누락되면 503 + degraded 형태로 응답합니다:

{ "ok": false, "degraded": true, "missing_tables": ["address", "admin_boundary"] }

에러 응답

모든 에러는 application/json 바디로 봉인됩니다(빈 바디·소켓 끊김 없음). 메시지는 절단될 수 있습니다.

HTTP상황응답 바디
400/reverse 의 lon/lat 누락·형식 오류{ "error": "lon/lat 필요" }
404미정의 경로{ "error": "not found", "endpoints": ["/geocode?q=", "/reverse?lon=&lat=", "/health"] }
500질의/DB/내부 오류{ "error": "질의 처리 오류: …" } (DB·내부 오류 동형)
503PostGIS 연결 실패·테이블 누락{ "error": "PostGIS 연결 실패: …" } 또는 health degraded

좌표 순서 주의: MapLibre 는 모든 곳에서 [경도(lng), 위도(lat)] 입니다. Leaflet 의 [lat, lng] 와 반대입니다.

폐쇄망 전환 후 기존 프론트의 MapTiler API 키 문자열은 더 이상 필요 없습니다. 공개 저장소에 노출된 키는 폐기하세요.
