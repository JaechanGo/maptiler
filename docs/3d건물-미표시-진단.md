# 부천 중앙부 3D 건물 미표시 진단보고서

## 1. 한줄 결론

증상의 지배 원인은 스타일 `minzoom 13`/`pitch`가 아니라 **martin이 부천 중앙부 building 타일을 빈 응답(HTTP 204)으로 서빙하는 스테일 캐시**다. martin 컨테이너가 데이터 적재(2026-06-24 23:39) 약 12시간 전(11:33)에 기동돼 데이터 공백기에 조회된 중앙 타일이 martin 인메모리 캐시(Moka, `cache_size_mb: 512`) + nginx L2 디스크 캐시(`proxy_cache_valid 200 204 7d`)에 빈 타일로 굳었고, 미재기동 상태라 영구 재서빙된다. 이와 별개로 `render_height` 최대 419,851,000m 가비지(원본 SHP A16 오염을 무검증 통과)가 시각 글리치를 유발하는 2차 결함이다.

## 2. "가운데 안 보임 / 가장자리 보임" 근본원인

### 결론: 의뢰 가설(스타일 minzoom 13 + pitch)이 아니라 **타일 제공 계층(martin 캐시)의 빈 타일(204)**

4개 조사 중 3개(스타일/줌, 커버리지, martin 실측)가 독립적으로 동일 결론에 수렴했다. 판별 결과는 "(b) 클라가 안 그림"이 아니라 **"(a) 타일이 비어서 옴"**이다.

**근거 1 — 타일 응답과 DB의 불일치 (결정적):**

| 항목 | 중앙 타일 (상동/중동) | 가장자리 타일 (송내동) |
|---|---|---|
| martin HTTP | 204 (0바이트, 4~5ms 즉답) | 200 (수십~수백 KB) |
| 예시 | `14/13961/6348`=204, `15/27923/12695`=204 | `14/13962/6349`=200(113KB), `15/27926/12697`=200 |
| DB 실제 건수 | `15/27923/12695`=1,477행, `14/13961/6348`=1,958~3,772행 | 정상 |
| PostGIS ST_AsMVT 재현 | `14/13961/6348` = **118,764바이트 / 3,775 feature** | 정상 |

즉 DB·SQL·SRID·지오메트리는 전부 정상인데 martin만 빈 타일을 반환한다. martin의 실제 쿼리 형태(`ST_AsMVTGeom(ST_Transform(geom,3857), ST_TileEnvelope(...),4096,64,true)`)를 PostGIS에서 그대로 재현하면 1,957 feature가 나온다.

**근거 2 — 밀도/타임아웃 무관, 지리적 경계:**
z15 그리드 24타일 스캔에서 204/200이 행(y) 기준으로 깔끔히 갈리며 DB 행수와 무관하다. `15/27923/12695`=DB 1,477행인데 204, `15/27926/12697`=DB 296행인데 200. 204 응답이 3~5ms 즉답이므로 "데이터가 많아 타임아웃"이 아니다. z14 격자 지도화 시 빈(204) 타일이 부천 중앙(x13957–13962, y6344–6349)에 **연속된 덩어리(blob)**로 뭉치고 사방을 풀(200) 타일이 둘러싼다 → 증상과 1:1 대응.

**근거 3 — 캐시 계층 확정:**
- nginx L2: 중앙 타일 `X-Cache-Status: HIT`. `gateway-nginx.conf` L78 `proxy_cache_valid 200 204 7d`로 204를 7일 영속.
- martin L1: nginx 캐시버스트(랜덤 버전 네임스페이스 `/dyn/vBUST.../`)로 강제 MISS시켜도 **여전히 204 반환(반복 3회 모두 MISS/204)**. martin은 타일 라우트에서 쿼리스트링을 무시하므로 nginx 버스트가 martin까지 닿지 않음 → 빈 응답은 martin 자체 in-process Moka 캐시에서 나온다.

**근거 4 — 타이밍이 빈 캐시를 설명:**
martin `StartedAt`=2026-06-24T11:33:47Z, building/building_41(부천 2,271,572행) 적재·ANALYZE=2026-06-24 23:39:33(기동 +12h). 기동 시 비어 있던 중앙 타일이 204로 캐시된 뒤 키(z/x/y) 동일·무효화 부재로 영구 재서빙된다. 동반 요인으로 부모 파티션 `public.building`의 `ST_EstimatedExtent` 실패(통계 부재 = ANALYZE 미반영)로 martin 소스 bounds 산정도 불안정하다.

### minzoom 13 + pitch 60은 2차(줌아웃) 요인일 뿐

`buildings` 소스(style.json)와 martin building 소스 모두 minzoom/maxzoom = **13/22로 일치**(불일치 아님). z<13 타일은 의도대로 404(`11/1745/793`, `12/3490/1587` 미서빙). pitch 60에서 base zoom 13으로 줌아웃하면 원경 실효 zoom≈11.5 → z11 타일이 minzoom 미달로 404되어 원경 건물이 사라진다. 단 **현재 보고된 z15 부근 증상에서는 204 캐시가 지배적**이고, 이 컷오프는 줌아웃 시 추가 악화 요인이다.

## 3. `render_height` 가비지(419M) 원인

### 결론: 원본 SHP A16이 잘못 → load_building.sh가 무검증 통과 (garbage-in/garbage-out)

원본 SHP(VWorld AL_D010) A16(높이m) 필드가 **이미 일부 레코드에서 오염**돼 있다:
- `A1=1985131761410410428900000000` → **A16=419,850,822.0** (원본 그대로), 같은 레코드 A17=12.11(정상 높이), A26(층수)=1
- `A16=19860913` = 1986-09-13 **날짜(YYYYMMDD)가 높이 자리에 침입**, 같은 레코드 A17=13.67(정상)

DB의 max=419,851,000은 원본 A16=419,850,822가 `real(float32)` 컬럼 저장 시 정밀도 손실로 반올림된 것이다(검증: `419850822.0::real`=419851000, `19860913.0::real`=19860900 — DB 저장값과 정확히 일치). **즉 load가 깨뜨린 게 아니다.**

**load 버그가 아님이 확정된 항목:** (1) 필드 인덱스 어긋남 X — ogrinfo 스키마상 A16=Real(18.15)=높이, A26=Integer=층수로 정의서대로 매핑, (2) 캐스팅 버그 X — `CAST(A16 AS REAL)` 타입 일치, (3) 단위 오류 X — 정상 행 A16은 m 단위로 맞음.

**구조적 결함:** `load_building.sh`(L92-94)의 산식은
```sql
CASE WHEN CAST("A16" AS REAL) > 0 THEN ROUND(CAST("A16" AS REAL),1)
     WHEN CAST("A16" AS REAL) > 0 THEN ROUND(CAST("A16" AS REAL)*3.3,1)  -- levels 경로
     ELSE 6 END
```
A16>0이면 **상한/이상치 검증 없이 그대로 채택**한다. 같은 레코드의 A17이 합리적 높이(12.11/19.98/35.89m)를 가질 때가 많은데 A17 대체 로직이 없다.

**규모:** 원본 가비지는 극소수(sido50 SHP 373,382건 중 A16>1000은 9건, 전국 >1000은 59건). 부천 sido 41은 >1000m 4건(max 757,465). `levels*3.3` 경로는 max(levels)=101 → 333.3m이므로 >1000은 절대 불가 → >1000 band 59건은 **전량 A16 경로 기인**.

전국 히스토그램(14,316,243행): 0-3m=56,177 / 3-15m=13,907,002 / 15-50m=317,701 / 50-200m=35,227 / 200-1000m=77 / **>1000m=59**.

**영향(시각 글리치):** `fill-extrusion-height = coalesce(render_height,15)`이므로 가비지 1동이 419,851,000m(지구 반경의 수십 배) 기둥으로 솟아 카메라 절두체·뎁스 버퍼를 점유한다. 단 부천 중앙 bbox max는 239m로 가비지가 없으므로(>500 0건), **부천 중앙 미표시 자체는 204 캐시가 원인이고 render_height 가비지는 별개의 데이터품질 이슈**다. (다만 화면 어딘가 시야에 들어온 거대 건물이 정상 건물을 가리는 글리치는 유발 가능.)

**수정안:** §5 참조.

## 5. 수정안 우선순위

### P0 — 즉효·무중단: martin 스테일 캐시 무효화 (재적재 불필요)
- **martin 재기동:** `docker compose restart martin` (기본 컨테이너명 `server-martin-1` — `docker-compose.yml` L152의 `martin:` 서비스에 `container_name` 미지정). Moka L1(`martin-config.yaml` L6 `cache_size_mb: 512`) 플러시 → 중앙 타일 204→200 전환.
- **nginx L2 무효화 (병행 필수):** `server/gateway-nginx.conf` L78 `proxy_cache_valid 200 204 7d`로 stale 204가 7일 잔존하므로, 재기동만으로는 nginx HIT가 남는다. 캐시 디렉터리(`martin_cache:/data/cache/martin`) purge 또는 스타일 tiles URL을 `/dyn/v<build>/` 버전 네임스페이스로 전환(키 분리로 무효화).
- **검증:** `/dyn/building/14/13960/6348`이 200/수십KB(≈1,957 feature)로 바뀌는지 즉시 재실측.

### P0.5 — 재발 방지 (빌드 파이프라인 순서 고정)
**`load_building.sh` 적재 → 부모/자식 파티션 ANALYZE → martin 재기동 → 캐시 무효화** 순서를 빌드 핸드오프에 강제. 부모 `public.building`(현재 `ST_EstimatedExtent` 실패=통계 부재) 및 자식(`building_41` 등) ANALYZE로 martin bounds 산정 정상화. nginx 204 TTL 분리 권장: `proxy_cache_valid 200 7d; proxy_cache_valid 204 30s;`(빈 응답 장기 캐시 차단).

### P1 — render_height 가비지 (근본 해결, 재적재 필요)
- **`scripts/postgis/load_building.sh` L92-94 CASE 식 수정** — A16에 신뢰 범위·우선순위 폴백 도입:
  ```sql
  CASE WHEN CAST("A16" AS REAL) BETWEEN 1 AND 500 THEN ROUND(CAST("A16" AS REAL),1)
       WHEN CAST("A17" AS REAL) BETWEEN 1 AND 500 THEN ROUND(CAST("A17" AS REAL),1)
       WHEN CAST("A26" AS REAL) > 0 THEN ROUND(CAST("A26" AS REAL)*3.3,1)
       ELSE 6 END
  ```
  우선순위 `A16(1~500) > A17(1~500) > A26*3.3 > 6`. 상한 500m(데이터 최고층 101층×3.3≈333m 대비 여유). 이는 가비지 59건·≤0 188건을 동시 정규화.
- **재적재 필요:** 산식 변경분은 신규 적재에만 반영되므로 building 테이블 재적재 또는 `UPDATE`로 기존 row 보정 필요.

### P1.5 — 스타일단 임시 클램프 (재적재 전 무중단 방어, 선택)
`style/style.json` `Building 3D`(L477) `fill-extrusion-height`를 상한 클램프로 감싼다:
```json
["min", ["coalesce", ["get","render_height"], 15], 500]
```
재적재 없이 거대 기둥 글리치를 즉시 차단. 단 임시방편이며 근본은 P1 적재식 수정.

### P2 — 줌아웃 원경 컷오프 완화 (선택)
줌아웃 시 원경 건물 소실을 줄이려면 minzoom 13→12로 1단계 완화(11은 z11 타일 면적이 z13의 ~16배라 과함):
- `style/style.json`: `buildings` 소스(L17)·`building-2d`(L322)·`Building 3D`(L466) minzoom 13→**12**
- `server/martin-config.yaml`: building 소스(L51) minzoom 13→**12** (style과 일치 유지)
- z12에서는 ST_AsMVTGeom 단순화/소형 건물 필터(render_height·면적 임계)로 타일 용량 억제 트레이드오프. **적정값: min 12 / max 22 (11 비권장).**

### P3 — use_type·name 적재 (표시/검색 품질, 부천 미표시와 무관)
필요 시 `load_building.sh`의 ogr2ogr SELECT·INSERT에 해당 A코드 필드 추가(컬럼정의서 매핑 확인 후). martin tilejson은 이미 `name` 필드를 노출하므로 적재만 하면 됨.
