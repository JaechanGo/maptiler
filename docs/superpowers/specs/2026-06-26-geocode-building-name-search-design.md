# 지오코더 건물명(단지명+동) 검색축 추가 — 설계

작성일: 2026-06-26 · 대상: `server/geocode-api-pg.py` (+ `server/test_geocode_api.py`)

## 배경 / 문제

`/geocode?q=다정한마을 2105동` 이 **빈 결과**를 반환한다. 해당 주소는 DB에 분명히 존재:

- `kind='addr'`, `bld='다정한마을 2105동(경남아너스빌)'`, 상동로 196, 좌표 (126.755165, 37.514653)
- 이런 **아파트 동(棟) 단위 주소가 305,744건** 적재돼 있음 (전부 `kind='addr'`, `bld` 컬럼).

### 근본 원인 (왜 빠졌나)

1. **`search_text` 생성컬럼이 `name + road + jibun`만 합침** (`scripts/postgis/schema/10-base.sql:57`).
   건물명/단지명(`bld`)이 제외 → addr 행은 단지명·동번호 텍스트로 검색 불가.
2. **이름 검색 경로가 `kind <> 'addr'` 한정** (`geocode-api-pg.py:461`). `bld ILIKE` arm은 있으나
   동번호가 든 `bld`는 전부 addr 행이라 이 경로에 안 잡힘.
3. 백로그 `docs/geocode-review-개선백로그.md:124` **B28(건물명 검색)** 이 미완 — 설계 스코프 누락.

= 지오코더가 **도로명 / 지번 / POI이름** 3축으로만 설계되고 **건물명(단지명+동) 검색축이 빠짐**.
데이터는 이미 있으니 **검색 경로만 추가하면 동작**.

## 결정 (사용자 확정)

- 범위: **전용 동번호 경로 + 일반검색 확장**(단지명만으로도 아파트 노출).
- 동번호 매칭: **정확매칭 + 단지 fallback**(동 못 찾으면 단지명으로라도 반환).

## 설계

### ② parse() — 동번호 토큰 분리

- 반환 dict 에 `bld_dong` 키 신설.
- 순수 `\d+동`(예 "2105동","101동") 토큰은 **법정동(dong) 아님 → `bld_dong`** 으로 분류, `terms`/`dong` 에서 제외.
- 한글 포함 동(상동·역삼동)은 기존 `dong` 유지. 단지명("다정한마을")은 `terms` 에 그대로.
- 회귀 안전: `dong` 분류 정규식을 `\d+동` 제외하도록만 보정 → 기존 법정동 동작 불변.

### ① 건물명(bld) 검색 경로 — 이름경로 직전, `if not results` 가드

도로명/지번 경로가 결과를 못 내고 `terms`(단지명 후보)가 있을 때 실행:

```sql
SELECT *, ST_X(geom) AS lon, ST_Y(geom) AS lat FROM address
WHERE kind='addr' AND geom IS NOT NULL
  AND bld ILIKE %s          -- 각 term ('%다정한마을%') AND, address_bld_trgm GIN 가속
  [AND bld ILIKE %s]        -- bld_dong 있으면 ('%2105동%') 추가, 정확
ORDER BY bld LIMIT 400
```

- 동번호 있으면 그 동 정확히(점수 195), 없으면 단지명만으로 단지 내 동들(점수 150 — station 175·place 165 보다 낮게 둬 'X역' 검색 회귀 방지).
- 결과는 기존 `addr_str`/`addr_obj`/`display_of(it, r)` 재사용 → 도로명주소 형태, 건물명 노출.
- **법정동 분리(구현 중 보정)**: `bld`(단지명+동)에는 행정구역명이 없으므로(emd/sigungu 별도 컬럼),
  `dong`(법정동) 토큰은 `bld` 매칭에서 제외하고 `emd = %s` 정확매칭으로만 사용. 안 그러면
  '도곡동 타워팰리스 101동' 처럼 법정동을 앞에 붙이면 `bld ILIKE '%도곡동%'` 가 0건을 유발.
- **성능 가드**: `bld_terms`(법정동 제외)+`bld_dong` 중 길이 ≥3 토큰(trgm 가능)이 1개 이상일 때만 실행.
  없으면(2자 단지명 단독 등) 경로 skip — 1570만행 Seq Scan 회피.
- **병합(`name_path`)**: 도로/지번 결과 유무를 미리 캡처해 bld 경로와 이름경로(POI/역)를 함께 실행·병합
  (네이버/카카오식 '주소 + 장소' 동시 노출).

### ③ fallback

- (terms AND bld_dong) 결과 0건 → `bld_dong` 빼고 terms 만으로 재쿼리(단지 동들 반환).
- 그래도 0건 → 이름경로(POI/버스정류장)로 자연 폴백.

### ① 일반검색 확장

- 위 bld 경로가 `terms` 만으로도 돌기 때문에 "다정한마을" 단독 → 아파트 주소 반환(=일반확장 충족).
- bld 경로 결과(addr)와 기존 이름경로(POI) 결과는 점수순 병합·dedup(기존 병합부 그대로).

### 회귀 안전

- 도로명("상동로 196")·지번("상동 514-8")·POI("강남역") 경로 미변경. bld 경로는 `if not results` 뒤.
- 표시/structure 계약(geocode/2) 불변 — 기존 addr 헬퍼 재사용.

## 테스트 (TDD)

DB불요 단위(parse) + DB통합(geocode, 컨테이너 실측):

1. `parse('다정한마을 2105동')` → `bld_dong='2105동'`, `dong is None`, `terms=['다정한마을']`
2. `parse('상동 514-8')` → `dong='상동'`, `house=(514,8)` (회귀)
3. (통합) `다정한마을 2105동` → 좌표 (126.755, 37.514) 반환
4. (통합) `다정한마을` → 아파트 주소 + 기존 POI 병합
5. (통합) `다정한마을 9999동`(없는 동) → 단지 fallback 결과 있음
6. (통합) `상동 514-8`·`강남역` → 회귀 없음
