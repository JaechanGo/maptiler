# 맵 렌더링 속도 리팩토링 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** maptiler 맵 렌더링 속도를, 데이터를 한 건도 누락·간결화하지 않고, build-studio 재빌드 산출물에 반영되는 방식으로만 개선한다.

**Architecture:** 서빙 스택(tileserver-gl + martin /dyn MVT + nginx 게이트웨이 + MapLibre style.json)에서 렌더링 비용을 만드는 4대 병목 — ① POI 과잉 서빙(z11 타일당 30.9MB/485k feature), ② PostgreSQL JIT 컴파일 오버헤드, ③ 죽은 스타일 표현식, ④ 브라우저/L2 캐시 부재 — 을 저위험 설정 변경(Wave 1·2)부터 데이터·스키마 수반 변경(Wave 3)까지 의존순으로 제거한다. 모든 변경은 repo 소스(style fragment·`style_objects.py`·`server/*.conf`·`docker-compose.yml`·`scripts/postgis`)에서 발생하고 `package.sh` 번들 → 폐쇄망 deploy로 흐른다.

**Tech Stack:** PostGIS 17-3.5, martin v0.18(동적 MVT), tileserver-gl v5.6, nginx 1.31-alpine, MapLibre GL JS, Python(build-studio·style_objects·build_style), bash 로더.

## Global Constraints

- **★데이터 무손실 절대**: POI/building/parcel 등 모든 원천 데이터는 PostGIS에 온전히 보존. "감축"은 삭제·간결화·우회가 아니라 **zoom 게이팅/라벨 디클러터(서빙 최적화)로만** 구현. 고줌(z15+/z17+)에서 전수 표시 불변. `WHERE` 필터·`minzoom`은 저줌 "표시 선택"일 뿐 테이블 전수보존.
- **★build-studio 반영**: 설정/스타일/스키마는 repo에 있고 `scripts/package.sh` 번들에 포함되어야 함. 런타임 수동변경만으로는 불충분. `style.json`은 `build-style.sh`로 재생성(직접편집 금지). `STYLE_STAGED`(staged/style/*.json) 존재 시 fragment 조립이 우회되므로 소스 수정 후 staged 정리 필수.
- **★package.sh 번들 한계**: `scripts/package.sh`는 `style/ demo/ vendor/ server/` + 일부 scripts만 번들하고 **`scripts/postgis/`는 미포함**. 따라서 SQL 스키마/함수 변경은 별도 번들 + deploy 적용경로 보강(Task 9) 필요. build-studio.py가 참조하는 `${BUILD_HOME}/deploy/docker-compose.yml` 존재 여부를 Task 1 착수 전 확인.
- **폐쇄망(air-gapped)**: 외부 CDN/프록시 불가 → 브라우저·L2 캐시 이득이 개방망 대비 크다. 배포호스트 RAM 미상이라 `docker-compose` 기본값 무분별 상향(OOM) 금지.
- **PG 영속 안전**: `fsync`/`synchronous_commit` 등 내구성 위험옵션 절대 미추가(기존 docker-compose 주석 정책). 성능 파라미터(`jit`)만 조정.
- **immutable 금지(조건부)**: `Cache-Control: immutable`은 버전 네임스페이스(`/dyn/v<build>/`, Task 7) 가동 후에만 부여. 미버저닝 immutable은 영구 stale로 데이터 갱신을 숨겨 데이터무손실 제약 위반.
- **검증 명령의 컨테이너명/포트**: 본 문서 `verify_command`의 `cuvia-postgis`·`cuvia-gateway`·포트는 예시 — 실제는 `docker compose ps`로 컨테이너명(예: `server-postgis-1`)·`GATEWAY_PORT`를 확인해 치환.

## Task 1: PostgreSQL JIT 비활성화

## Task 2: 캐시 정책을 theme.json 단일소스로 — 빌드가 nginx 캐시 블록 생성

**설계 변경(사용자 결정 · 2026-06-25):** `Cache-Control`은 HTTP 응답 헤더라 MapLibre `style.json` 스펙에 필드가 없다(거기 적어도 브라우저/nginx가 안 읽음). 대신 **style-studio가 편집하는 `style/theme.json`의 `cache` 섹션을 단일 소스**로 두고, 빌드가 `gateway-nginx.conf`의 마커 블록(`map`)을 생성한다. → 한 곳에서 설정 → 재빌드로 반영(사용자 비전). context7 확인: nginx `add_header`는 변수 지원, `map`으로 변수 산출 가능.

**병목:** 모든 타일 응답에 `Cache-Control` 부재 → 브라우저 반복 다운로드. (폐쇄망이라 캐시 이득 큼)

**분리 정책(데이터무손실·재빌드가시성)**: fonts/sprites=장기(`max-age=604800`), styles/data/files=단기 revalidate(`max-age=300, stale-while-revalidate=3600`), /dyn=`max-age=3600, stale-while-revalidate=86400`. ★`immutable`은 Task 7(버전 네임스페이스) 가동 후에만(미버저닝 immutable=재빌드 은폐).

**Files:**
- Modify: `style/theme.json` (`cache` 섹션 추가)
- Modify: `scripts/style_objects.py` (`CACHE_DEFAULT` + `sanitize_cache()` + `render_nginx_cache_block()`)
- Modify: `scripts/build_style.py` (theme.cache → `server/gateway-nginx.conf` 마커 블록 치환)
- Modify: `server/gateway-nginx.conf` (생성 마커 블록 + `add_header Cache-Control $static_cc/$dyn_cc`)

**Interfaces:**
- Produces: `gateway-nginx.conf`의 `# >>> GENERATED cache (style/theme.json) >>>` ~ `# <<< GENERATED <<<` 사이 `map` 블록을 build_style.py가 theme.cache에서 매빌드 재생성. http 컨텍스트 변수 `$static_cc`(자산별)·`$dyn_cc`(동적타일) 제공.

- [ ] **Step 1: theme.json `cache` 섹션 추가**
  ```json
  "cache": {
    "static_long":  "public, max-age=604800",
    "static_short": "public, max-age=300, stale-while-revalidate=3600",
    "dyn":          "public, max-age=3600, stale-while-revalidate=86400"
  }
  ```

- [ ] **Step 2: style_objects.py에 캐시 로직** — `CACHE_DEFAULT`(위 3값) + `sanitize_cache(c)`(키 화이트리스트 + 값은 안전 문자집합 `[a-z0-9,=\-\s]`만, 주입 차단) + `render_nginx_cache_block(cache)` → 다음 텍스트 반환:
  ```nginx
  map $uri $static_cc {
      default              "<static_short>";
      ~^/(fonts|sprites)/  "<static_long>";
  }
  map $request_uri $dyn_cc { default "<dyn>"; }
  ```

- [ ] **Step 3: gateway-nginx.conf에 마커 + add_header** — http 컨텍스트(proxy_cache_path 근처)에 마커 블록(초기 생성본) 삽입. 정적 location(`^/(styles|data|fonts|sprites|files)/`)에 `add_header Cache-Control $static_cc always;`, /dyn location의 `add_header X-Cache-Status` 다음 줄에 `add_header Cache-Control $dyn_cc always;`. (새 location/마운트 만들지 말 것 — map 한 방으로 분기)

- [ ] **Step 4: build_style.py에 생성 훅** — style.json 기록 후, theme의 `sanitize_cache(theme.get("cache")) or CACHE_DEFAULT`로 `render_nginx_cache_block()` 호출 → `server/gateway-nginx.conf`의 마커 사이를 멱등 치환(정규식). STYLE_IMPORT 경로에서도 동일 적용.

- [ ] **Step 5: 검증(라이브, gw=server-gateway-1:18080)**
  Run: `bash scripts/build-style.sh` → gateway-nginx.conf 마커 블록이 theme.cache 값으로 갱신됐는지 확인.
  `docker exec server-gateway-1 nginx -t && docker exec server-gateway-1 nginx -s reload`
  `curl -sI http://localhost:18080/styles/cuvia/style.json` → `max-age=300...`; `/fonts/x/0-255.pbf` → `max-age=604800`; `/dyn/poi/15/27000/12500` → `max-age=3600...`(+X-Cache-Status 유지).
  **단일소스 증명**: theme.json `cache.dyn` 값을 바꿔 `build-style.sh` 재실행 → 마커 블록이 따라 바뀌는지 확인 후 원복.
  회귀: style.json 200 정상(sub_filter `/dyn` 절대화 유지).

- [ ] **Step 6: Commit**
  ```bash
  git add style/theme.json scripts/style_objects.py scripts/build_style.py server/gateway-nginx.conf
  git commit -m "perf(cache): 캐시 정책 theme.json 단일소스화 — 빌드가 gateway-nginx 캐시블록 생성(자산별 분리)"
  ```

**data_safety:** 응답 헤더만, 타일 읽기전용. styles/data 단기 revalidate로 재빌드 즉시 반영. **build_studio_flow:** theme.json(style-studio 편집) → build_style.py가 gateway-nginx.conf 마커 생성 → package.sh가 server/ 번들 → deploy 시 nginx 반영. (style-studio UI에 캐시 탭 추가는 후속 선택)

## Task 3: POI 소스 minzoom을 style-studio(theme) 줌에서 자동 도출

**설계 변경(사용자 지적 · 2026-06-25):** POI 표시 줌은 이미 **style-studio가 `theme.json`(poi_tiers/cat_tiers/zoom)에서 관리**한다. `apply_poi_tiers()`(style_objects.py:388)는 poi-**label 레이어** minzoom을 tier 최소값으로 자동 설정하지만, poi **소스** minzoom(=11, poi-facilities.json)은 그대로라 z11~14에서 아무것도 안 그리며 거대타일만 페치(30MB 낭비의 정체). → 하드코딩 대신 **`apply_poi_tiers()`가 poi 소스 minzoom도 tier 최소값으로 자동 설정**해 단일소스화. style-studio에서 줌만 바꾸면 소스·레이어가 함께 따라감(절대 어긋나지 않음).

**근거(context7/MapLibre):** 클라이언트는 소스 `minzoom` 미만 줌에서 타일을 요청하지 않음 → 소스 minzoom 상향이 z11~14 페치를 차단. (overzoom은 maxzoom '위'에서만 발생, minzoom과 무관)

**Files:**
- Modify: `scripts/style_objects.py` (`apply_poi_tiers`: poi-label이 소비하는 소스의 minzoom = `min(tier minzoom)` 설정)
- Modify: `server/martin-config.yaml` (poi minzoom 정렬 — 보조/방어, 클라 페치는 style.json 소스 minzoom이 통제)
- Regenerate: `style/style.json` (직접편집 금지)

**Interfaces:**
- Consumes: theme.json `poi_tiers`(style-studio 편집).
- Produces: `style.json` sources.poi.minzoom = `min(poi_tiers.minzoom)` 자동.

- [ ] **Step 1: apply_poi_tiers에 소스 minzoom 도출 추가** — `L["minzoom"] = min(...)`(현 line 388) 직후에, poi-label이 참조하는 source명(`L.get("source")`)을 찾아 `style.get("sources",{}).get(src)`가 있으면 `src["minzoom"] = min(t.get("minzoom",15) for t in tiers)` 설정. (소스 다수 소비자 대비: 안전하게 poi-label의 source만 대상.)

- [ ] **Step 2: (보조) martin 정렬** — `server/martin-config.yaml` poi minzoom을 기본 tier 최소값(15)에 맞춤(서버측 방어). ※클라 페치 차단의 본질은 style.json 소스 minzoom.

- [ ] **Step 3: 재생성 + 검증**
  Run: `bash scripts/build-style.sh && python3 -c "import json;s=json.load(open('style/style.json'));print('src=',s['sources']['poi']['minzoom'],'layer=',[l for l in s['layers'] if l['id']=='poi-label'][0].get('minzoom'))"`
  기대: 기본 tier(t1=15)에서 `src=15 layer=15`.
  **단일소스 증명**: theme.json `poi_tiers`의 최소 minzoom을 14로 바꿔 재빌드 → `src=14`로 따라감 확인 후 원복.
  회귀: z(min tier)+ POI feature 수 불변(저줌만 게이팅).

- [ ] **Step 4: Commit**
  ```bash
  git add scripts/style_objects.py server/martin-config.yaml style/style.json
  git commit -m "perf(style): poi 소스 minzoom을 style-studio 티어에서 자동도출 — z11~14 거대타일 페치 차단, 소스·레이어 단일소스"
  ```

**data_safety:** 줌 게이팅만. PostGIS poi 전수보존, z(min tier)+ 전수표시. 소스 minzoom은 표시줌과 동기화될 뿐 데이터 삭제 아님. **build_studio_flow:** theme.json(style-studio) → apply_poi_tiers → style.json, package.sh 번들. martin-config은 server/ 번들.

## Task 4: nginx gzip 활성화 + L2 인코딩 분리 + PNG 이중압축 방지

**병목:** 현재 gzip off → MVT(protobuf/json) 비압축 전송. 단순 인코딩 분리(C3)는 gzip off 상태에선 no-op이므로 gzip 활성과 한 묶음으로만 유효.

**Files:**
- Modify: `server/gateway-nginx.conf` (http 컨텍스트 gzip·map, /dyn proxy_cache_key)

**Interfaces:**
- Consumes: Task 2(같은 conf 편집).

- [ ] **Step 1: gzip 활성(이미지 제외)** — http/server 컨텍스트:
