## 재평가 결론

- **work_mem 상향(기각 유지)**: 어떤 쿼리도 메모리 spill(외부정렬/디스크) 없음. 병목은 CPU(지오메트리)·플래닝 → work_mem 무효.
- **병렬도 전역 하향(기각 유지)**: parcel(68행)엔 4워커가 과하나 building(1,503행)엔 병렬이 execution 단축 → 전역 하향은 손해.
- **parcel M1(파티션 pruning 부재)**: 실재하나 대부분 상쇄 — martin prepared-statement(플래닝 연결당 1회) + 타일 캐시(martin L1 + nginx L2 + T7 `/dyn/v<build>`). parcel은 z16+(소영역)이라 캐시 적중률 높음. cold 타일 한정 비용.
- **building ST_Simplify(기각 유지)**: exec 182ms는 실재하나 ① martin이 이미 `clip_geom`+`extent=4096` 처리 ② 타일 캐시 상쇄 ③ 지적/건물 정밀도·폐쇄망 번들 리스크 → ROI 낮음.

## 향후(선택, 필요 시)

- **parcel 함수소스 `parcel_mvt(z,x,y)`**: 타일 bbox가 닿는 sido를 사전 산출 → `WHERE sido_cd = ANY(...)`로 18→1~2 파티션 pruning(poi_mvt 패턴, 데이터 무손실). cold 타일 플래닝/실행 개선. 측정상 캐시로 상쇄되므로 cold-타일 지연이 실제 문제일 때만.
