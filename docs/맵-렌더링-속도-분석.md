# 맵 렌더링 속도 분석 보고서

작성: 테크리드(성능) · 일자: 2026-06-24 · 범위: **분석 전용 — 실제 적용은 사용자 승인 후 별도 진행**

---

## 1. 한줄 결론 (최대 병목)

**최대 병목은 "POI 데이터 과잉"이며, 단일 원인이 서버·캐싱·스타일·클라이언트 4개 계층을 동시에 오염시키고 있다.** 구체적으로 (a) 동적 POI 저줌 타일이 feature 감축·simplify·중요도 컷 없이 생성되어 z11 단일 타일이 **30.9MB / 485,873 feature / cold 3.7s**(JIT 5.9s 포함)에 달하고, (b) 베이스 korea.mbtiles 도심 z14 타일은 **거의 렌더되지 않는 POI가 바이트의 66%**를 차지(이중 적재), (c) 스타일 `poi-label`은 **타일에 존재하지도 않는 `cat` 필드**를 feature마다 최대 10회 헛 비교하는 죽은 거대 표현식을 평가한다. POI 한 축만 정리해도 4개 계층이 함께 가벼워진다.

## 5. 빠른 승리 (Quick Win) 3가지

설정 변경 수준(저노력·저위험)으로 **승인 즉시** 가장 큰 비용 대비 효과를 내는 항목.

1. **PG JIT 회피 (N1)** — `ALTER ROLE <martin롤> SET jit=off` 한 줄로 poi z11 cold에서 JIT 5.9s, z12 6.1s, building z13 Emission 1.15s를 제거한다. 본 쿼리(Exec 2.7s/1.9s)는 그대로지만 **전체 cold 지연이 절반 가까이 단축**되며, 롤 단위라 다른 분석쿼리에 영향이 없다. 위험 거의 0, 효과 즉각. 단일 변경 중 ROI 최고.

2. **정적 자산 Cache-Control + L2 인코딩 분리 (N2 + N3)** — 게이트웨이 nginx에 (a) /(data\|styles\|fonts\|terrain) `Cache-Control: public, max-age=604800, immutable`, (b) `proxy_cache_key "$request_uri$enc"`(인코딩 정규화) 추가. **반복 팬/줌·재방문의 네트워크 왕복을 소거**하고 동시에 MVT 타일 대역폭을 ~50% 회수한다. nginx conf 수 줄. (immutable은 N7 버전 네임스페이스와 병행이 이상적이나, 데이터 갱신 주기가 주 단위 이상이면 단독으로도 안전.)

3. **poi-label 죽은 표현식·minzoom 정렬 (N5)** — style.json에서 (a) 항상 null인 `['get','cat']` 1차 match 분기(한글 10개 비교) 제거, (b) 데드 필터 `['!',['has','point_count']]` 제거, (c) poi source minzoom 11→15 정렬. **feature당 최대 10회 헛 문자열비교를 없애** 워커 심볼레이아웃 CPU를 즉시 낮추고, z11 14.6MB 거대타일 페치 위험을 원천 차단한다. 스타일 파일 한정 변경으로 데이터 경로 무영향. (case블록 7회 중복 제거·tier 사전계산은 효과가 더 크지만 회귀 검증이 필요하므로 N10/Next로 분리.)
