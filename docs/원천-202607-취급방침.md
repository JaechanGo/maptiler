## 3. 판정 — **B: 리포에 커밋하지 않는다**

커밋 가부는 **독립된 두 축**으로 나뉜다. 둘을 섞으면 결론이 흐려지므로 분리해 적는다.

### 3.1 축 1 — 개인정보: **해당하지 않음**

레이아웃 정의상 **자연인 식별정보 필드가 존재하지 않는다.** 두 가이드 PDF 붙임의
필드 목록 전체를 확인했고(주소 11 / 지번 11 / 부가정보 9 / 도로명코드 17 /
내비 건물 33 / 내비 지번 20 / 보조출입구 11), 성명·주민등록번호·전화번호·생년월일·
이메일에 해당하는 필드가 **한 건도 없다**. 샘플의 실제 필드 수도 위 정의와 전부 일치했다.

표본 스캔에서도 검출 0건이었다.

| 대상 | 규모 | 전화번호형 | 주민등록번호형 | 이메일형 |
|---|---|---:|---:|---:|
| zip 데이터 파일 전수(49개) | 각 60KB 선두 | 0 | 0 | 0 |
| 내비 건물정보 서울 | 11,941 행 | 0 | 0 | 0 |
| 주소·지번·부가정보 서울 | 138,037 행 | 0 | 0 | 0 |
| 도로명코드 전체분 | 28,203 행 | 0 | 0 | 0 |

**상세주소(동·호수) 논점** — 이 자료의 유일한 실질 쟁점이었다.

- 주소DB 주소정보 11번 `상세주소부여여부` 는 **0/1 플래그일 뿐 실제 동·호수 값이 없다.**
  전국 전량 6,422,308행을 스캔해 관측값 집합이 `{0, 1}` 뿐임을 확정했다
  (전국 `0`:5,609,608 / `1`:812,700 · 서울 파일 전량 523,345행 기준 `0`:327,910 / `1`:195,435).
- 내비 건물정보 20번 `상세건물명` 에는 **건물 동(棟) 표기가 수록된다**(예: `103동`, `본관동`).
- **세대 단위 호수가 실재한다.** ← **2026-08-20 정정.** 최초 조사는 서울 선두 표본
  11,941행(서울 전량 593,005행의 **2.01%**)에서 '숫자+호' 12건만 보고
  "세대 호수는 발견되지 않았다"고 단정했다. **이 단정은 철회한다.**
  서울 건물정보 **전량 593,005행** 재스캔 결과, 순수 '숫자+호' 값 **287건 중 245건이
  건축물용도분류=주택·거주여부=1** 이고, `101,201,301,401호` 처럼 **한 건물의 층별 세대
  호수를 나열한 값**(지상층수 4·공동주택구분 2 인 주택 등)이 실재한다. 관(館)명·역명·
  시설명으로는 설명되지 않는다. → **인용 제한은 §4.2-4 에 규정했다. 반드시 함께 읽을 것.**
- 부가정보 5번 우편번호일련번호·6번 다량배달처명은 **전량 공란**이었다(가이드 NULL 명시와 일치).

**두 사실을 뭉개지 말 것.** 아래 둘은 별개이며, 하나가 다른 하나를 상쇄하지 않는다.

| | 사실 | 귀결 |
|---|---|---|
| **호수는 있다** | `상세건물명` 에 세대 단위 호수가 실재한다(서울 전량 기준 확인) | 값 인용을 제한한다 → §4.2-4 |
| **이름은 없다** | 성명·주민등록번호·전화번호·생년월일·이메일에 해당하는 필드가 112개 필드 전체에 **0건** | 개인정보 축 결론은 유지된다 |

세대 호수는 **주소정보이지 그 자체로 자연인 식별정보가 아니다.** 건물 동 명칭도 건축물
자체의 명칭이지 특정 개인을 가리키지 않는다. 따라서 **이 축으로는 커밋을 막을 사유가 없다**
— 판정 B 의 사유는 §3.2 의 재배포 제한이며, 세대 호수의 발견은 그 결론을 뒤집지 않고
오히려 보수적 방향(커밋 금지)을 강화한다.

다만 "자연인 식별정보가 아니다"가 **"값을 자유롭게 인용해도 된다"는 뜻은 아니다.**
세대 호수를 위치 식별자와 함께 적으면 특정 건물의 세대 구성이 드러난다. §4.2-4 를 지켜라.

### 3.2 축 2 — 재배포 제한: **미해소**

**아카이브 안에 이용약관·라이선스 문서가 없다.** 두 가이드 PDF 전문에
`저작권|공공누리|이용약관|재배포|무단|허가|목적 외|제3자` 를 검색해 **0건**이었다.
즉 재배포 가부를 **실물 근거로 확정할 수 없다.**

그리고 두 자료의 지위가 다르다는 실물 근거를 찾았다.

| 자료 | 가이드가 밝힌 메뉴 경로 | 취득 조건 |
|---|---|---|
| 주소DB | 주소정보제공 > **공개하는주소** > 주소DB | 로그인 후 즉시 |
| 내비게이션용DB | 주소정보제공 > **제공하는주소** > 내비게이션용DB | **신청 후 승인 완료되어야 다운로드 가능** |

내비게이션용DB 가이드는 3곳(35·120·180행)에서 "제공하는 주소는 신청 후 승인이
완료되어야 다운로드가 가능합니다"라고 반복한다. **승인 기반으로 배포되는 자료를
공개 리포에 넣는 것은, 승인 절차 자체를 우회시키는 결과**가 된다.

**이 축이 커밋 금지의 실제 사유다.** 개인정보가 아니라 재배포 조건 미확인이다.

### 3.3 왜 A 가 아니고 왜 C 가 아닌가

- **A(커밋 가능)가 아닌 이유**: A 는 "개인정보 없음 **그리고** 재배포 제한 없음"이
  모두 성립해야 한다. 앞은 실증했으나 뒤를 실증할 수 없다.
- **C(보류)가 아닌 이유**: C 는 실행 지침을 주지 못한다. 지금 확정적으로 말할 수 있는
  것은 "커밋하지 않는다"이며, 이건 보류가 아니라 결론이다. 되돌릴 수 없는 쪽은 커밋이다.
- B 판정을 뒤집으려면 **약관 확인이라는 한 가지 작업만** 하면 된다(§6 참조).

## 4. 후속 태스크가 지켜야 할 규칙

**이 절이 T040(스키마 정밀 조사) 이후 태스크의 게이트다.** 판정 B 는 "원천 파일을
커밋하지 말라"이지 "이 자료를 쓰지 말라"가 아니다. 무엇이 되고 무엇이 안 되는지 적는다.

### 4.1 커밋해도 되는 것

- **필드 레이아웃·순서·자릿수·코드값 정의.** 가이드 PDF가 기술한 사실이며 데이터가 아니다.
  (예: "지하여부 = 0:지상 / 1:지하 / 2:공중 / 3:수상", "건물중심점 좌표는 GRS80 UTM-K")
- **집계 통계.** 행 수, 널 비율, 값 분포, 필드 수 검증 결과. 개별 레코드를 복원할 수 없다.
- **파서·검증 코드와 정규식.** 데이터를 담지 않는다.
- **직접 만든 합성 픽스처.** 실제 레코드를 베끼지 말고 레이아웃에 맞춰 새로 지어라.
  테스트 픽스처는 **반드시 이 방식**으로 만든다.

### 4.2 조건부로만 되는 것 — 샘플 값 인용

**문서 본문 안의 인용으로만** 허용한다. 아래 4조건을 **전부** 만족해야 한다.

1. 자연인 식별정보가 아닐 것(§3.1에 따라 해당 필드는 애초에 없다).
2. **특정 현상을 설명하기 위한 예시**일 것. 정렬·덤프·연속 추출은 금지다.
3. 총량이 데이터셋을 대체할 수 없는 수준일 것 — **문서당 20행 이내**를 상한으로 한다.
4. 자료별 등급을 지킬 것:
   - **주소DB(공개하는주소)** — 도로명·지번·건물명 등 값 인용 가능.
   - **내비게이션용DB(제공하는주소·승인 기반)** — 값 인용을 최소화한다.
     **좌표값은 인용하지 않는다.** 좌표가 이 자료의 핵심 부가가치이며 승인 사유다.
     좌표는 "범위", "자릿수", "EPSG:5179 여부" 같은 **성질로만** 기술하라.
     **`상세건물명`(20번) 필드의 개별 값도 인용하지 않는다.** 이 필드는 세대 단위 호수
     (`101,201,301,401호` 류의 층별 호수 나열)를 포함한다(§3.1). 필드의 존재·자릿수(100자)·
     널 비율·패턴 유형·집계 건수 같은 **성질로만** 기술하라.
     특히 값을 시도·시군구·읍면동·도로명·건물본번·건물관리번호 등 **위치 식별자와 짝지어
     적지 마라.** 값 하나만으로는 건물이 특정되지 않지만, 위치와 함께 적는 순간 특정 건물의
     세대 구성이 드러난다. 건물 동(棟) 표기(`103동` 류)처럼 세대성이 없어 보이는 값도
     같은 규칙을 적용한다 — 어느 값이 세대 호수인지 사전에 가려낼 공식 정의가 없기 때문이다
     (가이드의 `상세건물명` 항목은 **설명란이 비어 있다**, §6-6).
     불가피하게 패턴을 보여야 하면 **위치를 떼고 형태만** 쓰거나 합성 예시를 지어라.

     **자기참조 예외(엄격 한정).** 이 규칙을 설명하려면 규칙이 무엇을 막는지 보여야 한다.
     그래서 **이 문서(`docs/원천-202607-취급방침.md`) 본문이 §4.2-4 규칙 자체를 설명·예시할
     목적으로 드는 값**만 예외로 둔다 — 현재 §3.1·§4.2-4·§6-6 에 실린 `103동`·`본관동`·
     `101,201,301,401호` 3종이 전부다. 예외에는 아래 제약이 **전부** 붙는다.
     - **주체 한정.** 예외를 쓸 수 있는 것은 **이 문서뿐이다.** 다른 어떤 산출물도 원용할 수
       없다 — 다른 리포 문서, `.team/` 보고서, 커밋 메시지, PR·이슈 본문, 코드 주석,
       테스트 픽스처, 로그. *"취급방침이 `103동` 을 적었으니 이 금지는 절대적이지 않다"* 는
       해석을 **명시적으로 차단한다.** *"나도 규칙을 설명하려는 것"* 도 사유가 되지 않는다.
       규칙 설명은 이 문서의 일이며, 다른 문서는 **값을 옮기지 말고 §4.2-4 를 참조**하라.
     - **목적 한정.** 규칙의 설명·예시에 한한다. 데이터의 성질·분포·현상을 서술할 목적이면
       예외가 아니고 본문 규칙(성질로만 기술)이 그대로 적용된다.
     - **위치 식별자 짝짓기 금지는 예외 안에서도 그대로다.** 예외는 *값을 적어도 되는가*에만
       걸리고 *위치와 함께 적어도 되는가*에는 걸리지 않는다. 후자는 **예외 없이 금지**다.
       이 금지는 리포 밖 산출물(`.team/` 보고서 등)에도 동일하게 적용한다.
     - **확장 금지.** 이 문서에 **새 값을 더 추가하는 것도 예외가 아니다.** 규칙 개정으로
       불가피한 경우에 한해, 기존 3종으로 설명되지 않는 이유를 밝히고 §4.2 의 4조건을 다시
       통과시켜라. 가능하면 **합성 예시**를 쓰라.
     - **변형도 인용이다.** 값을 쪼개거나(`101호`·`201호` …) 고쳐 적거나 표로 나열하는 것도
       인용으로 본다. 실제 값의 나열은 어떤 형태로든 "성질 기술"이 아니다.
     - **규율 범위.** §4 가 규율하는 대상은 **리포에 커밋되는 산출물**이다(§4.1 "커밋해도
       되는 것" / §4.3 "커밋하면 안 되는 것"과 같은 축). 커밋되지 않는 작업 기록
       (`.team/` 보고서 등)에는 값 인용 자체를 금지하지 않는다. 다만 **위 짝짓기 금지는
       그대로 적용**되고, 거기 적힌 값을 **리포 산출물로 옮기는 것은 금지**다.
       주체 한정 목록에 `.team/` 보고서를 넣은 이유가 이것이다 — 예외를 원용할 자격을
       주지 않아 **작업 기록이 값을 리포로 실어 나르는 통로가 되는 것**을 막는다.

### 4.3 커밋하면 안 되는 것

- **원천 아카이브 자체**, 그리고 그 압축을 푼 데이터 파일.
- **지역 단위·전국 단위 부분집합.** "서울만"도 안 된다. 부분집합은 재배포다.
- **레코드를 담은 데이터 파일**(`.txt`/`.csv`/`.json`/`.sqlite` 무엇이든).
  §4.2 는 *문서 안의 인용*만 허용한다. 파일로는 안 된다.
- **내비게이션용DB의 좌표를 포함한 레코드**(양의 많고 적음과 무관).
- 원천을 그대로 담은 테스트 픽스처. §4.1의 합성 픽스처를 쓰라.

### 4.4 판단이 서지 않으면

**커밋하지 않는 쪽을 택하라.** 되돌릴 수 없는 쪽이 커밋이다.
리포 밖 `~/maptiler-rescue/source-202607/` 는 언제든 읽을 수 있으므로,
커밋을 미룬다고 정보가 사라지지 않는다.

## 5. 실수 방지 장치

`.gitignore` 에 원천 파일명 패턴을 등록했다(45~54행). 압축을 푼 파일이 워크트리에

```

주소_*.txt / 지번_*.txt / 부가정보_*.txt / 개선_도로명코드_*.txt
\[자료건수\]주소DB*.txt
```

- `[자료건수]` 는 glob 문자클래스로 해석되므로 `\[` `\]` 로 이스케이프해야 실제로 매칭된다.
- 등록 전 `git ls-files` 로 기존 추적 파일과의 충돌을 확인했다(매칭 **0건**).
- `git check-ignore -v` 로 양방향 실증했다: 무시되어야 할 11경로 전부 무시됨,
  무시되면 안 되는 3경로(`docs/*.md`, `scripts/15-score-595.py`) 전부 정상 추적.

**이 장치는 사고를 줄일 뿐 판정을 대신하지 않는다.** §4 규칙이 우선한다.

## 6. 이 판정의 한계 — 확인하지 못한 것

정직하게 적는다. 이 판정을 재검토할 사람이 알아야 한다.

1. **약관을 실물로 확인하지 못했다.** 아카이브에 약관 문서가 없고, 이 태스크는 네트워크
   조사를 범위에 넣지 않았다. 따라서 §3.2 는 "재배포 금지가 확인됐다"가 아니라
   **"재배포 허용이 확인되지 않았다"**이다. B 판정은 이 미확인 위에 서 있다.
2. **공공누리 유형 표기는 이 아카이브의 근거가 아니다.** 리포 `docs/data-licenses.md` §4 가
   기록한 "공공누리 1유형"은 **「도로명주소 전자지도·건물도형」** 항목이며,
   여기서 다루는 주소DB·내비게이션용DB와 **동일 항목이 아니다.** 혼동하지 말 것.
3. **개인정보 스캔은 전수가 아니라 표본이다.** 압축전 5.5GB 를 전량 훑지 않았다.
   zip 데이터 파일 49개의 각 선두 60KB + 서울 지역 파일 전량이 표본 범위다.
   단 아래 두 항목은 2026-08-20 수정 라운드에서 **전량으로 다시 측정**했다:
   주소DB `상세주소부여여부`(**전국** 6,422,308행)와 내비 건물정보 `상세건물명`
   (**서울 전량** 593,005행). 그 밖의 필드는 여전히 표본 근거다.
4. **세대 호수는 서울에서 이미 실재가 확인되었고, 전국 규모·분포는 미측정이다.**
   행 단위로 전량 스캔한 내비 건물정보는 `match_build_seoul.txt`(593,005행) 하나뿐이며,
   나머지 15개 시도 건물정보 파일은 스캔하지 않았다. 따라서 한계는 "다른 시도에는 없을지도
   모른다"가 아니라 **"서울에는 있다. 전국에 몇 건인지 모른다"**이다. 전국 계수는 T040 범위다.
   (**2026-08-20 정정** — 최초 서술은 서울 2.01% 표본에 근거해 한계의 방향이 반대였다.)
5. 필드 레이아웃은 **가이드 PDF 기술 + 샘플 필드 수 일치**로 확인했다. 각 필드의 의미를
   값 분포로 하나하나 검증한 것은 아니다(그 작업이 T040의 범위다).
6. **`상세건물명` 의 공식 정의가 없다.** 내비게이션용DB 가이드의 해당 항목(20번, 100자)은
   **설명란이 비어 있다.** "이 값은 세대 호수다"라는 §3.1 의 판단은 값의 형태
   (`101,201,301,401호`)와 동반 필드(용도=주택·지상층수 4·공동주택구분 2·거주여부 1)로부터의
   **추론이지 발행처 정의가 아니다.** 다만 이 추론이 틀렸더라도 "전부 관명·역명·시설명"은
   성립하지 않는다 — 용도=주택·거주=1 인 245건을 시설명이라 부를 수 없기 때문이다.
   §4.2-4 의 인용 금지는 이 불확실성 때문에 더 필요하다.

**B 판정을 A 로 바꾸려면**: business.juso.go.kr 의 두 자료 각각에 대한 이용약관/라이선스
