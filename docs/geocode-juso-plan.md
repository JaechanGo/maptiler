# 전체 도로명주소 지오코딩 구축 계획 (행안부 DB 적재)

목표: 사용자가 `"화성시 만세구 3.1만세로 5"` 같은 **전체 도로명주소 원문 1줄**을 던지면 좌표가 나오는
폐쇄망 자체 지오코더. 클라이언트는 주소를 쪼개지 않는다(서버가 정규화·매칭 전담).
현재 무의존 SQLite(FTS5+R-tree) 아키텍처를 유지·확장한다.

진행 순서: **A. 데이터 확보 → B. 파이프라인 구축 → C. 이미지 빌드/반입**. 좌표 데이터는
신청·심사(며칠 소요)가 필요한 장기 리드 항목이므로 **A를 먼저 착수**한다.

> 현재 한계: `geocode.sqlite`는 OSM 점 이름(역·지명·도로명·POI)·아파트 동·상가만 색인 →
> 전체주소(시·구·도로명·건물번호) 검색 불가. 본 계획은 그 공백을 행안부 공식 DB로 메운다.
> 배경·코드 위치는 [data-sources.md](data-sources.md), 라이선스는 [data-licenses.md](data-licenses.md) 참조.

## 0. 확정 사항 (2026-06-18)

- **모드 A — 전국 범용 지오코더**로 확정. 사용자가 임의의 전국 주소를 검색한다.
  → 토큰(OpenAPI)만으로는 불가: 검색 API는 **질의형(페이지 100건·일일 호출 제한·좌표 미제공)**
  이라 전국 600만 건을 받을 수 없다. **벌크 파일(건물DB + 위치정보요약DB)이 필수**,
  토큰은 검증·증분 보조용.
- 빌드 흐름 **온라인 빌드 → 이미지/번들 → 폐쇄망 반입**으로 확정
  ([scripts/package.sh](../scripts/package.sh)의 기존 에어갭 구조 재사용 — §C).
- 매칭 로직은 [scripts/geocode-juso-poc.py](../scripts/geocode-juso-poc.py)로 **검증 완료(6/6)**:
  전체주소 단건 확정 · `3.1만세로` 토큰 함정 방어 · 건물번호(523) prefix 오염 차단 ·
  본번/부번 구분 · 동명이 도로 다중후보 · 역지오코딩.

## A. 데이터 확보

### A-1. 받아야 할 파일 (공식 카탈로그로 확정)

다운로드 페이지의 카탈로그 API(`api/jst/download` 응답)로 확정: **`RLS_YN` 플래그가 공개/심사를
가른다. `Y`=공개(즉시 다운로드, 좌표 없음·텍스트 속성만) / `N`=신청·심사(좌표·도형 포함).**

| 구분 | 데이터 | RLS_YN | 심사 | 용도 |
|---|---|---|---|---|
| 텍스트(공개) | **건물DB** | Y | 불필요 | 건물단위 도로명주소 + 지번. 시도/시군구/읍면동/도로명/본번·부번/우편번호 |
| 텍스트(공개) | 주소DB | Y | 불필요 | 주소단위(집합건물 1건) + 관련지번(약 600만+800만) |
| 텍스트(공개) | 도로명주소 한글 | Y | 불필요 | 도로명주소 기준 약 600만 건 (사용자가 받은 `RNADDR_KOR`) |
| 텍스트(공개) | 상세주소DB | Y | 불필요 | 동·층·호 (2차, 수천만 행) |
| **좌표(심사)** | **내비게이션용DB ★** | **N** | **필요** | **건물단위 주소 + 좌표(건물중심점·주/보조출입구)를 한 파일에 — 우리 목적 최적** |
| 좌표(심사) | 위치정보요약DB | N | 필요 | 주소 + 좌표 결합 요약 (ITRF2000/GRS80) |
| 좌표(심사) | 도로명주소 출입구 정보 | N | 필요 | 출입구 좌표(주/보조) |
| 좌표(심사) | 전자지도(SHP) | N | 필요 | 건물·출입구·행정경계 11종 도형 (UTM) |
| 참고 | 활용가이드 ZIP | Y | 불필요 | 정확한 컬럼 순서·바이트 레이아웃(스키마 확정) — [건물DB](https://juso.go.kr/dn.do?fileName=buldDBAddrGuide.zip) |

**핵심(확정)**: 공개(RLS_YN=Y)는 **전부 텍스트, 좌표 없음** — 사용자가 받은 `RNADDR_KOR`(도로명주소
한글)도 좌표 미포함. **좌표가 붙은 데이터는 전부 RLS_YN=N → 신청·심사**. 우리 목적엔
**내비게이션용DB(건물단위 주소+좌표가 한 파일)** 가 최적 — 텍스트·좌표 별도 조인 없이 **단일 소스로
빌드** 가능(단 심사 필요). 텍스트만 따로 쓸 땐 관리번호(bdMgtSn, PK)로 좌표와 조인.

### A-2. 좌표 데이터 신청 절차 (장기 리드 — 먼저 착수)

- 대상: **내비게이션용DB(권장)** 또는 위치정보요약DB. 근거: 도로명주소법 시행령 §46, 시행규칙 §53
  — 신청서 + 이용목적 심사.
- **제공 범위별 승인 주체**: 시군구=해당 자치단체 / 2개 이상 시군구=시도지사 / **전국=행정안전부
  승인**. 우리는 전국 범용 → **행안부 승인 경로**(가장 시간 소요).
- 위치: [business.juso.go.kr 제공하는 주소(도형/좌표)](https://business.juso.go.kr/jst/jstAddressDownload) → "제공하는 주소(도형, 좌표)" 탭 → 신청.
- 라이선스: 공공저작물 **출처표시 제1유형(CC-BY)** + 이용목적 범위 준수. **폐쇄망 반입 전
  신청서상 이용목적·재배포 조건을 반드시 확인**하고 [data-licenses.md](data-licenses.md)에 기재.
- ⛏ **이 항목을 오늘 신청**해 두면 심사 대기 중에 나머지를 진행할 수 있다.

#### 신청 목록 (심사) — 검토 확정

| 판정 | 데이터 | 이유 |
|---|---|---|
| **필수 ★** | **내비게이션용DB** | 건물단위 주소+좌표(+지번·건물명) 단일 파일. forward 본체 + reverse 최근접점 |
| **권장** | **도로명주소 전자지도** | reverse 행정구역경계(시도/시군구/읍면동/법정리) 폴리곤 + 건물 폴리곤(매칭 정밀도). 같은 전국 심사라 함께 받을 가치 큼 |
| 선택 | 위치정보요약DB | 내비DB의 **부분집합(중복)**. 빼도 무방, 백업으로 둬도 부담 적음 |
| ❌ 제외 | 민원행정기관 전자지도 | 관공서 POINT POI — 주소 지오코딩 기여 0, 게다가 구버전(2024.01). 심사 정당화만 늘림 |
| ❌ 제외 | 내부도로 전자지도 | 건물 *내부* 통로 — 옥외 주소↔좌표와 도메인 불일치 |

→ **추천 세트 = 내비게이션용DB + 도로명주소 전자지도** (위치정보요약DB는 선택).
한 신청서에 담아 **전국 = 행정안전부** 승인. 이용목적에 **"폐쇄망 내부 지오코딩 서버 구축·운영,
외부 재배포 없음"** 명시 + 산출물 출처표시(공공누리 제1유형).

#### 추가로 받을 공개자료 (심사 불필요 — 검색 텍스트 측 보강)

좌표는 위 심사DB로 충분하지만, 검색 인덱스의 **텍스트**가 비어 추가 필요(전부 무료·즉시):
- **활용가이드/레이아웃 정의서** — 컬럼 파싱 전제. **없으면 적재 불가**(치명).
- **건물DB** — 지번↔건물 매핑(~1,000만)·건물명 보강(내비DB에도 있으나 커버리지 보강).
- (필요시) **상세주소DB** — 동/층/호. 단 동·호 자체 좌표는 없어 **건물 좌표로 귀착**.
- 조인 키 = **건물관리번호(BD_MGT_SN, 25자리)** — 심사DB(좌표)↔공개DB(텍스트) 결합 축.

#### 공개(텍스트) 다운로드 URL 패턴 — 빌드 자동화용 (확인됨)

공개(RLS_YN=Y) 데이터는 로그인 세션으로 직접 다운로드 가능:
```
GET https://business.juso.go.kr/api/jst/download
    ?reqType=<데이터코드: 예 ALLRNADR_KOR=도로명주소 한글 전체분>
    &ctprvnCd=00          # 00=전국 (또는 시도코드)
    &stdde=YYYYMM         # 기준 월 (예 202605)
    &regYmd=YYYY&realFileName=<zip>&intFileNo=0&intNum=0
```
→ 온라인 빌드 단계에서 최신 월 파일을 자동 수집(reqType 코드는 건물DB용으로 별도 확인).
좌표(RLS_YN=N) 데이터는 심사 승인된 계정 세션으로만 받는다(공개 URL 불가).

### A-3. 파일 포맷·인코딩 (확인됨)

- 포맷: **TXT, 파이프(`|`) 구분자, 헤더 없음**. (= 행안부가 이미 컬럼을 나눠 제공 → "파싱"이
  아니라 컬럼 매핑이면 충분)
- 인코딩: **CP949** → UTF-8 변환 필요. `iconv -f CP949 -t UTF-8 build_경기.txt > build_경기.utf8.txt`
- 분할: **시도별 분할** (`build_<시도>.txt` 등) → 적재 시 병합.
- 좌표계(확인됨): 신청 5종 **전부 EPSG:5179 (UTM-K, GRS80, 미터)**. 내비DB/요약DB도 실제 X/Y는
  경위도가 아니라 UTM-K(juso 매뉴얼 명시) · 전자지도 SHP = 5179. → **빌드 단계에서 4326으로 1회
  변환**(B-2). 5179↔4326은 격자(grid) 없이 수학변환이라 **오프라인에서도 정확**(5174 Bessel 계열과 달리 안전).

## B. 파이프라인 구축 (데이터 수령 후)

### B-1. 적재 단위 결정

- **1차: 건물 단위(집합건물 1건)** — 약 600~700만 행. SQLite 단일 파일 3~6GB, 검색 ms급.
- 2차(별도): 상세주소(동·호) 전개 — 수천만 행/15~25GB. prefix·external-content 최적화 전제.
- ⇒ **1차는 건물 단위로 한정**.

### B-2. 전처리 (좌표계 변환)

현재 스크립트는 외부 의존 0(표준 라이브러리만, [07-gen-geocode.py:16](../scripts/07-gen-geocode.py)).
5179→4326은 표준 라이브러리로 불가 → **ogr2ogr 전처리로 분리**(스크립트 무의존 원칙 유지):

```bash
# 좌표(위치정보요약DB/전자지도)를 4326으로 변환
ogr2ogr -t_srs EPSG:4326 juso_coord_4326.geojson juso_coord_5179.shp
# 텍스트는 CP949 → UTF-8
iconv -f CP949 -t UTF-8 build_경기.txt > build_경기.utf8.txt
```

### B-3. 스키마 변경 — [07-gen-geocode.py:196](../scripts/07-gen-geocode.py)

`places`에 도로명주소 분리 컬럼 추가(또는 별도 `addr` 테이블). 핵심: **건물번호는 텍스트가 아닌
INTEGER 컬럼**(`main_no`/`sub_no`)으로 — prefix 오염(`5*`가 `523` 매칭) 원천 차단.

```sql
-- 도로명주소 구조화 컬럼 (type='road_addr')
sido TEXT, sigungu TEXT, emd TEXT,
road TEXT, road_norm TEXT,          -- 원형 / 정규형('31만세로')
main_no INTEGER, sub_no INTEGER,    -- 본번 / 부번(없으면 0)
postal TEXT, bld_name TEXT, full_addr TEXT
-- FTS5: 회수용, 컬럼 분리해 bm25 가중 제어
CREATE VIRTUAL TABLE places_fts USING fts5(
  region, road, bld,                -- 행정구역 / 도로명(표기변이 동시색인) / 건물명
  content='places', content_rowid='id', tokenize='unicode61', prefix='2 3');
```

### B-4. 추출기 추가 — [07-gen-geocode.py:226](../scripts/07-gen-geocode.py)·[:232](../scripts/07-gen-geocode.py)

- `--juso-csv` / `--juso-geojson` 인자 추가, `all_rows()`에 `extract_juso()` 연결.
- `extract_juso()`: 건물DB(텍스트) + 좌표(관리번호 조인) → 구조화 5튜플 생성. `extract_poi_csv()`
  의 헤더 자동매핑 패턴 재사용.
- dedup 키 분기([07-gen-geocode.py:206](../scripts/07-gen-geocode.py)):
  `road_addr`는 `(typ, sido, sigungu, road, main_no, sub_no, lon5, lat5)`.

### B-5. 색인 함정 방어 (`.`·숫자+한글)

`unicode61`은 `3.1만세로`를 `3`/`1만세로`로 쪼갬 → `31만세로`로 치면 0건.
→ **색인에 표기 변이를 모두 수록**: `road` 컬럼에 `"3.1만세로 31만세로 삼일만세로"`,
정밀 비교는 `road_norm='31만세로'`(점 제거) 컬럼으로. 색인·질의에 **동일 정규화 함수** 적용.

### B-6. 검색 로직 — [geocode-api.py:51](../server/geocode-api.py)

현재 "전부 AND"([geocode-api.py:51](../server/geocode-api.py))는 동을 빼먹으면 즉시 0건 → **단계적 폴백**:

1. 정밀: `road` 필수 + `region` 가산 + `main_no/sub_no` SQL equality
2. 번호 완화(부번 무시) → 3. 지역 완화(가산점만) → 4. 도로 only(다중 후보 반환)

랭킹은 명시 score: `정확매칭 > 도로+번호 > 도로 > 동 > 시`. 1·2등 격차 임계 미달이면
`candidates[]`로 반환(전국 동명이 도로 대비). bm25 컬럼 가중은 `road`를 압도적으로.

### B-7. 역지오코딩 (좌표 → 풀주소 1줄)

R-tree bbox 회수 → `cos(lat)²` 보정 최근접 1건 → `sido+sigungu+emd+road+본번(-부번)` 조립.
박스 단계 확대(50m→200m→1km), 0건이면 읍면동 중심 폴백(`precision:"emd"`).

### B-8. 빌드 성능 (대량 INSERT)

빌드 PRAGMA: `journal_mode=OFF; synchronous=OFF; cache_size=-1048576; temp_store=MEMORY`.
수만 행 배치 트랜잭션 → FTS5 `'rebuild'` → `'optimize'` → R-tree/인덱스 생성 → `VACUUM`.
인덱스 절감: `prefix='2 3'`(한글 2~3자면 충분), external content, 필요시 `detail=column`.
런타임은 읽기전용(`query_only=ON`) — 다중 reader 동시성 OK.

## C. 이미지 빌드 & 폐쇄망 반입

기존 에어갭 파이프라인([scripts/package.sh](../scripts/package.sh))을 그대로 활용한다. geocode
컨테이너는 prebuilt `geocode.sqlite`만 읽으므로([server/docker-compose.yml](../server/docker-compose.yml)),
도로명주소를 적재한 sqlite를 번들에 포함하면 끝이다.

1. **온라인 빌드 머신**: 벌크 파일 → ogr2ogr/iconv 전처리(B-2) → `07-gen-geocode.py --juso-*`
   → `geocode/geocode.sqlite`
2. **검증(선택)**: 토큰으로 OpenAPI 실주소 대조 + PoC 재실행
3. **번들**: `scripts/package.sh` → `dist/images.tar`(docker save) + 산출물 tgz(geocode.sqlite 포함)
4. **폐쇄망**: 반입 → `docker load` → `docker compose up` → geocode-api가 sqlite 서빙

- **보안**: 토큰은 **빌드 단계 환경변수로만** 사용. 이미지/번들엔 결과 sqlite만 들어가고 토큰은 미포함.
- **갱신**: 월 1회(또는 일변동) 새 파일로 재빌드 → 새 번들 반입. sqlite 교체 후 컨테이너 재기동.
