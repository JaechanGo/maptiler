# 지번(parcel) 검색 최적화 — 작업 요약

> 브랜치: `feature/postgis-refactor` · 목표: 도로명만 되던 주소검색에 **지번 검색** 추가 및 성능 최적화
> 설계 상세: [geocode-jibun-parcel-plan.md](geocode-jibun-parcel-plan.md)

## 1. 문제 진단

| 항목 | 상태(작업 전) |
|------|--------------|
| 도로명 검색 | ✅ `address(road_norm,main_no,sub_no)` B-tree 정확매칭 |
| 지번 검색 | ⚠️ 코드는 있으나 ① fallback 전용 ② `search_text ILIKE '%동%'`(짧은 번지 trgm 미적용) ③ 권위 소스 `parcel`(39.6M) **미연동** |

**근본 원인**: 전국 연속지적도 `parcel` 테이블이 검색에 연결돼 있지 않고, 정규화 컬럼·대표점·인덱스도 없어 빠른 지번 lookup이 불가능.

## 2. 적용한 아키텍처

### 2.1 parcel 정규화 (`scripts/postgis/schema/21-parcel-jibun.sql`)
```sql
ALTER TABLE parcel
  ADD COLUMN ji_main int,   -- 본번 (jibun 파싱)
  ADD COLUMN ji_sub  int,   -- 부번 (없으면 0)
  ADD COLUMN san     smallint,            -- 산(임야) 여부
  ADD COLUMN geom_pt geometry(Point,4326);-- ST_PointOnSurface 대표점
CREATE INDEX parcel_jibun_lookup ON parcel (emd_cd, ji_main, ji_sub);
```

### 2.2 법정동명 → emd_cd 사전 (`lawd_dong`)
- parcel엔 `emd_cd`(8자리)만 있고 동명이 없어, 법정동 경계 SHP에서 `(emd_cd, emd)` 추출
- **동명은 정확 등가(`=`) 매칭** — `ILIKE '%동%'` 금지(2자 동명 Seq Scan 차단)

### 2.3 지번 백필 (`scripts/postgis/backfill_parcel_jibun.sql`)
- `jibun`('[산]본번[-부번][지목]') → `san/ji_main/ji_sub` 파싱 + `geom_pt` 대표점

### 2.4 질의 경로 (`server/geocode-api-pg.py`)
```
지번질의: 동명 → lawd_dong(emd 정확매칭) → emd_cd 후보
        → parcel WHERE sido_cd=ANY(left(cds,2)::char(2)[])  -- ★캐스팅 필수(파티션 pruning+인덱스)
                       AND emd_cd=ANY(cds::char(8)[])
                       AND ji_main=? AND ji_sub=?
        → COALESCE(geom_pt, ST_PointOnSurface(geom)) 좌표 반환
도로명 경로(:120-143): 무변경
```

## 3. 검증 결과 (경기/경남 E2E — 라이브 API 입증)

| 질의 | 결과 | 좌표 |
|------|------|------|
| 수원 영통구 매탄동 1-11 | 매탄동 1-11 대 | 127.0581, 37.2711 ✅ |
| 성남 분당구 정자동 178-1 | 정자동 178-1대 | 127.1052, 37.3595 ✅ |

- ⚡ **지연 평균 2.9ms** (10회)
- 🔍 EXPLAIN: 파티션 pruning(1개) + `parcel_jibun_lookup` Index Scan, 실행 **1.2ms**
- 🐛 char(2/8) vs text 배열 **캐스팅 버그 수정** — 전 파티션 Seq Scan → 1파티션 Index Scan

## 5. 완료 상태 (최종)

- [x] parcel 전국 적재 — **34.9M / 17시도** (188/188 파일)
- [x] **parse 백필** — ji_main **100%**(NULL 41행). 경북/충남 int4 오버플로 버그 발견·수정(자릿수 가드)
- [x] **M4 재검증** — 전국 라이브 동작, EXPLAIN 파티션 pruning+인덱스 확인
- [x] **적대적 검증 워크플로우** — 골든셋 100%, HIGH 결함 4건 적발
- [x] **결함 4건 수정+재검증** — 읍/면 동명, 동명중복 시도 narrowing, limit 가드, backfill 가드 → 골든 51/51·시도접두 17/17·엣지 전부 통과, 회귀 0
- [x] **geocode-pg 컨테이너 8092 기동** — 전국 지번 스모크 통과(~7ms)

### 발견·수정한 결함 (적대적 검증)
1. **읍/면 동명 미해결** — parse()가 `동|리`만 인식 → `동|리|읍|면` (geocode-api-pg.py)
2. **동명중복 시도 미좁힘** — SIDO_NM 사전으로 시도 엄격 한정 추가
3. **limit 비숫자 crash** — `_limit()` 안전 파서
4. **backfill int4 오버플로** — 자릿수≤7 가드 (backfill_parcel_jibun.sql)
